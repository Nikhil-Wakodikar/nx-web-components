# Form Template 

This comprehensive form template demonstrates all available input components from the stencil-library in a single, reusable form structure. It showcases best practices for form composition, validation, and layout.

---

## Overview

The Form Template provides pre-built form layouts that combine multiple input components into cohesive, production-ready forms. These templates are designed to:

- **Accelerate Development** - Copy and customize complete forms
- **Ensure Consistency** - Follow established patterns and best practices
- **Simplify Validation** - Centralized validation with `bfl-form-wrapper`
- **Responsive Layout** - Mobile-first, accessible designs

## FAQs

<details>
<summary>How do I customize the spacing between form fields?</summary>

Adjust the `gap` property on `bfl-stack-layout`:

```html
<bfl-stack-layout gap="24px">
  <!-- form fields -->
</bfl-stack-layout>
```

Common values: `12px` (tight), `16px` (default), `24px` (spacious)
</details>

<details>
<summary>How do I handle form validation?</summary>

The `bfl-form-wrapper` handles validation automatically. Each input component validates its own rules (required, format, etc.). The form will only submit if all validations pass.

```html
<bfl-form-wrapper submitId="myFormSubmit">
  <!-- Required fields are validated automatically -->
  <bfl-text-input name="name" isRequired="true"></bfl-text-input>
  
  <!-- Submit button -->
  <bfl-cta-button 
    submitId="myFormSubmit" 
    isSubmit="true"
    label="Submit">
  </bfl-cta-button>
</bfl-form-wrapper>
```

Listen to the `formSubmitted` event to access validated data.
</details>

<details>
<summary>Can I have multiple submit buttons?</summary>

No, use only one submit button per form. For additional actions (like "Save Draft"), use regular buttons with `isSubmit="false"`.

```html
<bfl-button-group button-count="2">
  <!-- Regular button -->
  <bfl-cta-button 
    name="draft" 
    type="outlined" 
    isSubmit="false">
  </bfl-cta-button>
  
  <!-- Submit button -->
  <bfl-cta-button 
    name="submit" 
    type="gradient" 
    isSubmit="true" 
    submitId="formSubmit">
  </bfl-cta-button>
</bfl-button-group>
```
</details>

<details>
<summary>How do I pre-fill form values?</summary>

Set the `value` attribute on input components:

```javascript
// From API or localStorage
const userData = await fetchUserData();

document.querySelector('[name="fullName"]').setAttribute('value', userData.name);
document.querySelector('[name="email"]').setAttribute('value', userData.email);
// etc.
```

In Angular:

```html
<bfl-text-input
  name="fullName"
  [value]="userData.name"
  label="Full Name">
</bfl-text-input>
```
</details>

<details>
<summary>How do I make a field optional?</summary>

Simply don't set `isRequired="true"` (or set it to `false`) and remove validations from `formControls` :

```html
<!-- Required field -->
<bfl-text-input 
  name="email" 
  isRequired="true">
</bfl-text-input>

<!-- Optional field -->
<bfl-text-input 
  name="middleName" 
  isRequired="false">
</bfl-text-input>
```
</details>

## Troubleshooting

<details>
<summary>Form not submitting</summary>

**Problem:** Clicking submit button doesn't trigger `formSubmitted` event.

**Solution:**
1. Ensure `submitId` matches between `bfl-form-wrapper` and `bfl-cta-button`
2. Check that submit button has `isSubmit="true"`
3. Verify all required fields are filled and valid
4. Check browser console for validation errors

```html
<!-- IDs must match -->
<bfl-form-wrapper submitId="myForm">
  <bfl-cta-button submitId="myForm" isSubmit="true"></bfl-cta-button>
</bfl-form-wrapper>
```
</details>

<details>
<summary>Validation not working</summary>

**Problem:** Form submits even when required fields are empty.

**Solution:**
1. Make sure `bfl-form-wrapper` wraps all input components
2. Verify `isRequired="true"` is set on required fields
3. Check that each input has a unique `name` attribute

```html
<!-- Correct structure -->
<bfl-form-wrapper submitId="form">
  <bfl-text-input name="field1" isRequired="true"></bfl-text-input>
  <bfl-text-input name="field2" isRequired="true"></bfl-text-input>
  <bfl-cta-button submitId="form" isSubmit="true"></bfl-cta-button>
</bfl-form-wrapper>
```
</details>

<details>
<summary>Dropdown options not showing</summary>

**Problem:** Dropdown is empty or doesn't display options.

**Solution:**
Ensure options array has correct format with `id`, `value`, and `showValue`:

```javascript
// Wrong - missing properties
const options = ['Option 1', 'Option 2'];

// Correct
const options = [
  { id: 1, value: 'opt1', showValue: 'Option 1' },
  { id: 2, value: 'opt2', showValue: 'Option 2' },
];
```

In HTML:
```html
<bfl-dropdown-input name="field" .options=${options}></bfl-dropdown-input>
```
</details>

<details>
<summary>Spacing looks inconsistent</summary>

**Problem:** Form fields have uneven spacing.

**Solution:**
Use `bfl-stack-layout` with consistent `gap` value:

```html
<!-- Good -->
<bfl-stack-layout gap="16px">
  <bfl-text-input></bfl-text-input>
  <bfl-email-input></bfl-email-input>
</bfl-stack-layout>

<!-- Avoid custom margins -->
<bfl-text-input style="margin-bottom: 10px"></bfl-text-input>
```
</details>

<details>
<summary>Event not firing in Angular</summary>

**Problem:** `formSubmitted` or other events not captured in Angular.

**Solution:**
1. Add `CUSTOM_ELEMENTS_SCHEMA` to your module
2. Use correct event binding syntax `(eventName)`
3. Call `defineCustomElements()` in main.ts

```typescript
// app.module.ts
import { CUSTOM_ELEMENTS_SCHEMA } from '@angular/core';

@NgModule({
  schemas: [CUSTOM_ELEMENTS_SCHEMA]
})

// main.ts
import { defineCustomElements } from 'stencil-library/loader';
defineCustomElements();

// component
<bfl-form-wrapper (formSubmitted)="onSubmit($event)"></bfl-form-wrapper>
```
</details>

<details>
<summary>Back button confirmation not showing</summary>

**Problem:** Want to show confirmation dialog before navigating away.

**Solution:**
Listen to `backButtonClicked` event and handle navigation manually:

```javascript
const header = document.querySelector('bfl-app-header');

header.addEventListener('backButtonClicked', (e) => {
  e.preventDefault(); // Prevent default navigation
  
  if (hasUnsavedChanges()) {
    const confirmed = confirm('You have unsaved changes. Continue?');
    if (confirmed) {
      window.history.back();
    }
  } else {
    window.history.back();
  }
});
```
</details>

<details>
<summary>Form data structure unclear</summary>

**Problem:** Don't know how to access form data from `formSubmitted` event.

**Solution:**
The event detail contains an object with field names as keys:

```javascript
formWrapper.addEventListener('formSubmitted', (e) => {
  console.log(e.detail);
  /* Output:
  {
    fullName: { value: 'John Doe', valid: true },
    email: { value: 'john@example.com', valid: true },
    phoneNumber: { value: '1234567890', valid: true },
    ...
  }
  */
  
  // Access specific field
  const name = e.detail.fullName.value;
  const email = e.detail.email.value;
  
  // Check if all fields valid
  const allValid = Object.values(e.detail).every(field => field.valid);
});
```
</details>

## Best Practices

1. **Always use `bfl-form-wrapper`** - Required for validation and submission
2. **Unique field names** - Each input must have a unique `name` attribute
3. **Match submitId** - Ensure form wrapper and submit button have matching `submitId`
4. **Consistent spacing** - Use `bfl-stack-layout` with uniform `gap` values
5. **Required fields** - Mark mandatory fields with `isRequired="true"`
6. **Event handling** - Listen to `formSubmitted` for form data, not individual button clicks
7. **Validation feedback** - Use `has-custom-error` and `custom-error-message` for custom validation
8. **Responsive design** - Forms are mobile-first by default, test on various screen sizes
9. **Accessibility** - All components have built-in ARIA labels and keyboard navigation
10. **Draft saving** - Implement draft functionality for long forms to prevent data loss
